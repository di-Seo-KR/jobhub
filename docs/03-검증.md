# 03. 검증 (Verification)

설계대로 산출물이 만들어졌는지, 상호 일관성이 있는지 점검한 결과.

## 1. 구조 점검
- 총 파일 **33개** 생성.
  - 에이전트 8 / 지식 5 / 템플릿 6 / 체크리스트 2 / 예제 8(README 포함) / 문서 4 / 진입점(README, CLAUDE.md) 2 등.
- 설계 문서(`02-설계.md`)의 목표 파일 구조와 일치. ✅

## 2. 에이전트 정의 유효성
- 8개 에이전트 모두 `name`, `description`, `tools`, `model` frontmatter 보유. ✅
- 모델 배정: 창작·판단(intake-strategist, resume-writer, resume-reviewer, interview-coach) = opus / 분석(jd-analyst, experience-miner, interview-designer) = sonnet / 조사(market-researcher) = sonnet. ✅
- 도구 최소권한: 일반 에이전트 `Read, Write, Edit, Glob, Grep`, 리서처만 `WebSearch, WebFetch` 추가. ✅
- **실측 확인**: 8개 에이전트가 Claude Code 세션에 정식 등록되어 호출 가능 상태로 인식됨. ✅

## 3. 상호 참조 일관성
- 에이전트·CLAUDE.md가 참조하는 `knowledge/`·`templates/`·`checklists/` 경로 **13개 전부 존재, 누락 0건**. ✅
- 각 에이전트의 입력/출력이 다음 단계의 입력과 연결됨(핸드오프 체인 단절 없음). ✅

## 4. 다이어그램
- `02-설계.md`의 Mermaid 2종(flowchart, sequenceDiagram) 문법 정상, 코드펜스 짝 일치. GitHub에서 네이티브 렌더. ✅
  - (참고: MCP 미리보기 도구는 SVG/PNG 응답 용량 초과로 오류를 냈으나, 이는 미리보기 도구의 출력 크기 한계일 뿐 다이어그램 자체는 유효함.)

## 5. 워크플로우 일관성 (예제로 검증)
`examples/sample-candidate`의 7단계 산출물이 하나의 서사로 연결되는지 확인:
- JD 핵심역량(SQL·분석→액션) → 경험 카드(#1 이탈분석) → 자소서 문항1·2 → 면접 질문 Q3·Q4 → 답변 스크립트까지 **사실·수치 일관**. ✅
- 약점(실무 데이터 경험 부재)이 프로필→질문(Q8)→답변(전환 프레임)으로 일관 관리. ✅
- 자소서 정량 수치(리텐션 13%p, 객단가 12%)가 면접 꼬리질문으로 검증되고 [확인 필요]로 표기됨(윤리 원칙 준수). ✅

## 7. 알려진 한계 / 향후 보완
- 산업·직군별 세부 지식 모듈 미포함(현재 범용) → `knowledge/industry/*`로 확장 가능.
- 실시간 채용공고 크롤링 없음 → `market-researcher` 웹검색으로 보조.
- 음성/영상 모의면접은 텍스트 기반으로 대체.
