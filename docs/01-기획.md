# 01. 기획 (Planning)

## 1. 배경 & 문제 정의

한국의 취업 준비생은 다음과 같은 어려움을 겪는다.

- **자소서**: 문항마다 무엇을, 어떻게 써야 할지 막막하다. 글자수 제한 안에서 직무역량을 설득력 있게 담기 어렵다. 클리셰("어릴 적부터", "열정", "최선을 다하겠습니다")로 채워진다.
- **경험 정리**: 본인의 경험 중 무엇이 어필 포인트인지 모른다. 경험을 STAR로 구조화하지 못한다.
- **면접**: 어떤 질문이 나올지 예측이 안 되고, 답변을 두괄식·근거 중심으로 구성하지 못한다. 압박/PT/토론 등 유형별 대비가 부족하다.
- **정보 비대칭**: 기업 인재상, 채용 프로세스, 직무 실제 업무, 산업 동향에 대한 정보가 부족하다.

기존 솔루션(혼자 작성, 단발성 첨삭, 일반 챗봇)은 **일관성·전문성·엔드투엔드 연계**가 부족하다. 자소서와 면접이 따로 놀고, 직무 분석 없이 글만 다듬는다.

## 2. 목표 (Goal)

> **한 팀이, 직무 분석부터 자소서·면접·전략까지 일관되게 책임지는 취업 컨설팅 시스템**을 만든다.

- 지원자의 **실제 경험**을 발굴·구조화하여 직무에 맞게 표현한다.
- 채용공고의 **핵심역량**과 경험을 정합적으로 연결한다.
- 자소서 → 예상 질문 → 면접 답변이 **하나의 맥락**으로 이어진다.
- 한국 취업시장 관행(문항형, 글자수, 블라인드/NCS, 인적성·AI면접)을 반영한다.

## 3. 범위 (Scope)

### In Scope
- Claude Code 서브에이전트 기반 **컨설팅 팀** 구축 (8개 에이전트)
- 팀 오케스트레이션 가이드(`CLAUDE.md`)
- 한국 취업시장 **지식베이스**, **템플릿**, **체크리스트**
- 엔드투엔드 **워크드 예제**(가상 지원자)

### Out of Scope (이번 단계)
- 독립 실행 웹/CLI 애플리케이션, DB, 인증
- 실시간 음성 모의면접(텍스트 기반으로 대체)
- 기업별 실시간 채용공고 크롤링 파이프라인(필요 시 `market-researcher`가 웹 검색으로 보조)

## 4. 페르소나 & 핵심 시나리오

| 페르소나 | 상황 | 핵심 니즈 |
|---|---|---|
| **취준생 A (신입)** | 첫 공채 지원, 경험 정리가 막막 | 경험 발굴 + 자소서 처음부터 |
| **이직 희망자 B (경력)** | 경력기술서·직무 자소서 필요 | 직무역량 정리, 성과 정량화 |
| **마감 임박 C** | 3일 뒤 마감, 빠른 완성 필요 | 자소서 초안 + 첨삭 빠르게 |
| **면접 직전 D** | 서류 합격, 면접 임박 | 예상 질문 + 답변 + 모의면접 |

**대표 시나리오 (풀 패키지)**
1. A가 "○○기업 ○○직무 풀세트 준비" 요청
2. 인테이크로 프로필·목표 진단 → 컨설팅 플랜 수립
3. 채용공고 분석으로 핵심역량·키워드 도출
4. 경험 은행 구축(STAR 소재)
5. 문항별 자소서 작성 → 첨삭 → 재작성
6. 예상 질문 풀 생성 → 답변 설계 → 모의면접
7. 최종 종합 리포트로 마무리

## 5. 팀 구성안 (8 Agents)

| # | 에이전트 | 미션 | 주 산출물 |
|---|---|---|---|
| 1 | `intake-strategist` | 진단·전략·총괄 | 컨설팅 플랜, 종합 리포트 |
| 2 | `jd-analyst` | 채용공고/직무/기업 분석 | JD 분석서(핵심역량·키워드) |
| 3 | `experience-miner` | 경험·경력 구조화 | 경험 은행(STAR) |
| 4 | `resume-writer` | 자소서 작성 | 문항별 자소서 초안 |
| 5 | `resume-reviewer` | 자소서 첨삭·평가 | 첨삭본 + 평가 점수 |
| 6 | `interview-designer` | 예상 질문 설계 | 질문 풀(유형별) |
| 7 | `interview-coach` | 답변·모의면접 | 답변 스크립트, 피드백 |
| 8 | `market-researcher` | 시장·기업 리서치 | 리서치 브리프 |

## 6. 성공 기준 (Definition of Done)

- [ ] 8개 에이전트가 명확한 역할·도구·핸드오프 규칙으로 정의됨
- [ ] `CLAUDE.md`에 팀 운영/라우팅 규칙이 정의됨
- [ ] 지식베이스·템플릿·체크리스트가 한국시장 기준으로 작성됨
- [ ] 엔드투엔드 워크드 예제가 동작 흐름을 증명함
- [ ] 모든 산출물이 상호 참조 일관성을 가짐(검증 단계 통과)

## 7. 위험 & 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 경험 과장·창작 유도 | 신뢰성·윤리 문제 | 모든 에이전트에 "창작 금지·검증 전제" 원칙 명시 |
| AI 자소서 검출/표절 | 탈락 위험 | 개인 경험·구체 수치 중심, 본인 소화 강조 |
| 에이전트 간 맥락 단절 | 산출물 불일치 | 표준 템플릿 + 핸드오프 산출물로 맥락 전달 |
| 기업/직무 정보 부정확 | 오답변 | `market-researcher` 웹검증, 출처 명시, 추정은 추정으로 표기 |
